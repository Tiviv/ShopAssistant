# Магазинер за ИИ асистенти (MCP конектор)

Тази папка е MCP сървър: малка програма, през която Claude (а по-късно и
ChatGPT) може да чете данните на магазина, когато собственикът пита например
„Колко направихме днес в брой?“ или „Колко струват доматите?“. Работи и от
телефона, през приложението на Claude.

**Версия 0.1 е само за четене.** Нищо не може да се променя или изтрива.

## Как работи (накратко)

```
Claude ──(въпрос)──> shop-mcp (Supabase Edge Function) ──(като вас)──> база данни
   │                        │
   └── вход ──> Supabase Auth (OAuth 2.1) ──> страница за разрешение (oauth/consent/)
```

1. Добавяте конектора в Claude с адреса на функцията.
2. Claude ви праща към страницата за разрешение. Влизате със **своя** акаунт в
   Магазинер и натискате „Разреши“.
3. Claude получава ключ (token), който важи само за вашия акаунт и изтича сам.
   Всяка заявка към базата минава **от ваше име**, така че същите правила
   (Row Level Security) като в уеб приложението пазят данните на магазина.

### Защо е направено така (за портфолиото)

| Решение | Защо |
|---|---|
| Supabase Edge Function, отделна папка | Не пипа уеб приложението и `main`; деплойва се отделно. |
| Вход с OAuth през Supabase Auth | Няма нови пароли или ключове; ползва същите акаунти. |
| Заявки с ключа на потребителя, **никога** `service_role` | RLS важи и тук; дори бъг в сървъра не може да покаже чужди данни. |
| Приема само ключове, издадени през OAuth (`client_id`) | Откраднат ключ от уеб приложението не става за конектора. |
| 6 инструмента, всичките само за четене | Моделът не подава SQL, имена на таблици или колони. |
| zod проверка + горни граници на всеки списък | Грешни или огромни заявки се спират преди базата. |
| Списък с познати приложения на страницата за разрешение | Непознато приложение може само да бъде отказано. |
| Списък с позволени `client_id` (`SHOP_MCP_ALLOWED_CLIENTS`) | След като Claude се свърже, само той може да ползва сървъра. |
| Запис в логовете кой кой инструмент е ползвал | Одит без да се записват самите данни. |

### Инструменти

| Име | Какво прави |
|---|---|
| `shop_day_summary` | Касата за ден (по подразбиране днес, часова зона София): в брой / карта / банка, приключен ли е денят |
| `shop_closed_days` | Последните приключени дни |
| `shop_find_products` | Търсене на продукти: цена, мерна единица, наличност |
| `shop_list_documents` | Фактури / оферти / кредитни известия / стокови разписки, с филтри |
| `shop_get_document` | Един документ по номер, с редовете |
| `shop_find_customers` | Търсене на клиенти |

## Какво трябва да знаете за сигурността

- **Данните отиват при доставчика на ИИ.** Когато Claude отговаря, той вижда
  отговора на инструмента: суми, имена на клиенти, телефони. Това е като да ги
  поставите в чата. За клиенти, които са физически лица, това е лична
  информация (GDPR).
- **Prompt injection.** Ако някой текст в базата (напр. име на клиент) съдържа
  „инструкции“, моделът може да се обърка. Затова версия 0.1 е само за четене;
  записите ще идват с изрично потвърждение.
- **Функцията OAuth Server на Supabase е в бета.** Затова първо тестов проект.
- **Как се спира достъпът:** махнете конектора в Claude, а в Supabase
  Authentication → OAuth Apps изтрийте приложението. Ключовете изтичат сами до
  час.

## Тестване: стъпка по стъпка

Всичко става в **отделен, безплатен тестов проект**. Живият магазин не се пипа.

### 1. Тестов Supabase проект

1. supabase.com → **New project**. Име например `shopassistant-test`, регион
   Frankfurt. Запишете паролата на базата.
2. **SQL Editor → New query**: поставете целия `supabase/schema.sql` → **Run**.
3. **Authentication → Users → Add user → Create new user**: имейл и парола за
   тест, отметнете **Auto Confirm User**.
4. **SQL Editor → New query**: поставете `supabase/mcp-test-data.sql`, сменете
   имейла на ред 12 с този от стъпка 3 → **Run**. Ще видите
   „Test data added“. (Скриптът отказва да пише, ако акаунтът вече има данни.)

### 2. Включване на входа (OAuth) в тестовия проект

1. **Authentication → URL Configuration → Site URL**: `http://localhost:3000`
2. **Authentication → OAuth Server**: включете го.
   - **Authorization Path**: `/oauth/consent/`
   - **Dynamic client registration**: включено (Claude се регистрира сам).
3. (Препоръчително) **Project Settings → JWT Keys**: ако пише, че ползвате
   „Legacy JWT secret“, натиснете миграция към нови ключове (ECC/RSA).
   Работи и без това, но е по-бързо и по-сигурно.

### 3. Страницата за разрешение на вашия компютър

1. В `oauth/consent/index.html` попълнете тестовите стойности:
   ```js
   "localhost": { url: "https://<тестов-проект>.supabase.co", anonKey: "sb_publishable_..." },
   ```
   (Project Settings → API Keys → **Publishable key**. Не `secret`/`service_role`!)
2. В папката на репото пуснете: `python3 -m http.server 3000`
   (или `npx serve -l 3000 .`) и го оставете да работи.

### 4. Качване на функцията в тестовия проект

От папката на репото (трябва Node.js; Docker не е нужен):

```bash
npx supabase login
npx supabase functions deploy shop-mcp --project-ref <тестов-ref> --no-verify-jwt --use-api
```

`<тестов-ref>` е частта преди `.supabase.co` в адреса на тестовия проект.
`--no-verify-jwt` е нарочно: първата заявка на Claude идва без ключ, за да
разбере къде да влезе. Функцията сама проверява всеки ключ.

Адресът на конектора е:
`https://<тестов-ref>.supabase.co/functions/v1/shop-mcp/mcp`

### 5. Проба с MCP Inspector (на компютъра)

```bash
npx @modelcontextprotocol/inspector
```

В прозореца: Transport **Streamable HTTP**, URL от стъпка 4 → **Open Auth
Settings → Quick OAuth Flow**. Ще се отвори страницата за разрешение, влизате
с тестовия акаунт → **Разреши**. После **Connect → Tools → List Tools** и
пробвайте `shop_day_summary`.

### 6. Проба в Claude (и от телефона)

1. claude.ai → **Settings → Connectors → Add custom connector**.
   Име `Магазинер (тест)`, URL от стъпка 4.
2. **Connect** → страницата за разрешение → вход → **Разреши**.
   Запишете си **ID на приложението** от страницата.
3. Нов чат, включете конектора и питайте, например:
   - „Колко направихме днес и колко от това е в брой?“
   - „Кои фактури не са платени?“
   - „Колко струват доматите и колко имаме?“
   - „Покажи ми фактура 1003.“
4. Телефон: отворете приложението Claude със същия акаунт. Конекторът е там.
   (Входът става веднъж, от браузъра на компютъра, защото страницата за
   разрешение е на `localhost`.)

### 7. Заключване само за Claude

Със записаното ID:

```bash
npx supabase secrets set SHOP_MCP_ALLOWED_CLIENTS=<ID> --project-ref <тестов-ref>
```

После можете да изключите **Dynamic client registration**, за да не може
никой друг да се регистрира.

## Към живия магазин (по-късно, само с ваше одобрение)

1. `oauth/consent/index.html` влиза в `main` (нова отделна страница; самото
   приложение не се променя). Ще е на
   `https://shopassistant.svejoivkusno.com/oauth/consent/`.
2. В живия проект: OAuth Server → Authorization Path `/oauth/consent/`
   (Site URL вече е домейнът на магазина).
3. `npx supabase functions deploy shop-mcp --project-ref mrkhgsvfizmmcairbtey --no-verify-jwt --use-api`
4. Свързване в Claude и заключване (стъпки 6–7) с живия адрес.

## Настройки (Supabase secrets)

| Име | По подразбиране | Значение |
|---|---|---|
| `SHOP_MCP_ALLOWED_CLIENTS` | празно (всички одобрени) | Списък с `client_id`, разделени със запетая |
| `SHOP_MCP_ALLOW_SESSION_TOKENS` | `false` | Само за локални тестове с ръчно поставен ключ |
| `SHOP_MCP_ALLOWED_ORIGINS` | празно | Браузърни сайтове, които могат да викат директно |
| `SHOP_MCP_PUBLIC_URL`, `SHOP_MCP_AUTH_ISSUER` | от `SUPABASE_URL` | Само при локално пускане |
